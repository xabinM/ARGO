## 1.3 빌드 및 배포

### **배포 아키텍처**
- **CI/CD**: GitLab Runner (EC2에 설치)
- **트리거**: master 브랜치 push
- **빌드**: S3에 빌드 파일 저장 후 EC2로 전송
- **Backend**: JAR 파일로 직접 실행 (Docker 미사용)
- **AI Server**: Docker Compose로 컨테이너 실행

### **배포 파이프라인 단계**

**3단계 순차 실행:**
1. `build_backend` - Backend JAR 빌드 및 S3 업로드
2. `deploy_backend` - Backend 서버 배포 및 재시작  
3. `deploy_ai` - AI 서비스 Docker 컨테이너 배포

### **Backend 빌드 단계**
- OpenJDK 17 환경에서 Gradle 빌드 실행
- JAR 파일 생성
- AWS CLI로 S3에 `bogoargo-backend.jar` 이름으로 업로드
- S3에서 JAR 파일 다운로드
- SSH로 서버 접속하여 배포 실행
- 기존 프로세스 종료
- JAR 파일 교체 (백업 포함)
- 새 Spring Boot 애플리케이션 시작

### **AI 서비스 배포 단계**
- AI 코드를 tar.gz로 압축
- S3에 업로드
- 서버로 파일 전송 및 배포
- 기존 서비스 백업
-  새 코드 압축 해제
- 환경변수 파일 생성
- Docker Compose로 서비스 재시작
- Health Check 수행

### **배포 프로세스 요약**

1. **개발자가 master 브랜치에 push**
2. **build_backend_job**: Spring Boot JAR 빌드 → S3 업로드
3. **deploy_backend_job**: S3에서 다운로드 → EC2에서 교체 → 서비스 재시작
4. **deploy_ai_job**: AI 코드 압축 → 서버 전송 → Docker Compose 재빌드
5. **자동 Health Check 및 실패 시 롤백**

### **Step 3: Android APK 빌드**
```bash
cd frontend/
./gradlew assembleRelease

# APK 위치: app/build/outputs/apk/release/app-release.apk
```

## 1.4 배포시 특이사항

### **A. 네트워크 설정**
- **HTTP 허용**: `network_security_config.xml`에서 HTTP 트래픽 허용 설정
- **CORS**: Backend에서 프론트엔드 도메인 허용 필요

### **B. Firebase 설정**
- **FCM 서비스 계정 키**: `backend/src/main/resources/firebase/` 위치에 JSON 파일 필요
- **google-services.json**: Android 앱의 패키지명과 일치해야 함

### **C. SSL/TLS**
- **HTTPS 설정**: 프로덕션 환경에서는 SSL 인증서 필요
- **Mixed Content**: HTTPS에서 HTTP API 호출시 브라우저 차단 가능

### **D. 메모리 및 성능**
- **AI 서버**: GPU 사용시 CUDA 설정 필요, 최소 4GB RAM 권장
- **Backend**: JVM 힙 메모리 설정 (`-Xmx2g` 권장)
